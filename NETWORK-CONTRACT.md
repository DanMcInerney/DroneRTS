# Network increment integration contract

Root owns game.ts/index.ts/shared/types.ts/client, package setup, and server/network.ts. Zenoh maker owns network/peer.py, supporting Python files named peer_*, tests/network-peer.test.ts. MAVLink maker owns server/mavlink.ts, network/mavlink.py, tests/mavlink.test.ts, MAVLINK.md. No source overlap. Python executable defaults to .venv/Scripts/python.exe (Windows) or .venv/bin/python; FLEET_PYTHON may override. Root supplies server/python-rpc.ts (PythonRpc) for newline JSON child IPC.

PythonRpc constructor(scriptPath, args=[], onEvent?, pythonPath?) with async start(): Promise<void>, request(method, params={}, timeoutMs=10000): Promise<any>, stop(): Promise<void>. Start resolves on {event:'ready',...}. stdin requests {id,method,params}; stdout {id,result} or {id,error:string}; notifications {event,...}. stdout is protocol-only. Processes exit when stdin closes. Bind network sockets to 127.0.0.1 only. Use OS ephemeral ports, not fixed shared ports.

Zenoh worker arguments: --drone drone-1 --session UUID --listen tcp/127.0.0.1:PORT --peers comma-separated other two endpoints --store absolute sqlite file. Exactly three processes, native peer mode, no central router. Scouting multicast/gossip off; explicit TCP endpoints. worker methods send({message,ttlMs?}), link({online:boolean}), consume({ids:string[]}), status({}), stop({}). send takes existing fleet-radio/1 message, requires from own drone, matching session and valid recipient; queues durable outbox and returns {queued:true,id}. Group = other two known recipients, direct = one. Native Zenoh group/direct topics and ACK topic, retries stable IDs until per-recipient receipt or expiry. Receiver persists before ACK, deduplicates; emit {event:'received',message} once per new arrival and on startup for unconsumed inbox. Node consumes only after handing a message to the model. Link false closes Zenoh session (simulates a node network partition); link true reopens it. Keep outbox while isolated. On all receipts emit {event:'delivery',id,status:'received',recipients:[...]}; expiration emit status:'expired'. Emit {event:'status',online,pending,...} updates. No inference from worker. Worker self-contained so messages go through Zenoh, not parent forwarding. Internal authenticated/capability local-only PoC; no claim of hardened network authentication.
