# DroneRTS development

This standalone Three.js RTS has two teams of three drones hauling finite salvage, sharing delivered income, choosing equipment and fighting until one team survives. The map is the sourced 820 × 660 m downtown Cincinnati landmark core; `shared/downtown.json` owns its extent. Read [README.md](README.md), [ARCHITECTURE.md](ARCHITECTURE.md), [CITY.md](CITY.md), [NETWORK.md](NETWORK.md) and [MAVLINK.md](MAVLINK.md), plus [ONBOARD.md](ONBOARD.md) for lossless sensor encoding. Read [QA-HANDOFF.md](QA-HANDOFF.md) for current open QA issues, the portable collision reproduction and the smaller-map validation.

The authorized [implementation handoff](DRONE-RTS-IMPLEMENTATION-HANDOFF.md) and [execution refinement](ONBOARD-FEEDBACK-REFINEMENT.md) supersede the old cube-mining, miner-shop and calibration/privacy restrictions for the cargo/onboard revision. The user-authorized cargo-v2 revision removed batteries, charging and power-loss deaths. Current cargo-v3 starts unarmored with zero shared salvage, removes optics purchases, and places both bases and three finite caches on rooftops. The authorized graphics revision adds physical flashing navigation/apron lights and nearly transparent collision walls/ceiling; these supersede the old nonemissive-prop restriction. Historical reports and recordings retain their original rules and meaning.

## Run and verify

- Build the pinned unpublished Nervelet package with `npm run nervelet:setup`, install JavaScript dependencies with `npm ci`, and install Python helpers with `npm run network:setup`. Node 24+ is required by Nervelet and supplies per-thread routine CPU accounting. Python dependencies belong in `.venv`; see `NERVELET-QA.md` for the tested interpreter.
- Read `RELIABILITY-QA.md` for current implementation checks, `NERVELET-INTEGRATION.md` for the exact dependency, and `CAMERA-AGE-POLICY-QA.md` for the unresolved native held-wait camera gate. `NERVELET-UPGRADE-QA.md` preserves historical upgrade evidence. Completed new images retain honest timestamps/age; the two-second camera freshness flag is descriptive, not a delivery gate. Missing/invalid pixels, finite acquisition deadlines and physical range-sensor expiry remain separate. Setup builds the exact unmerged source commit without private patches; set `NERVELET_SOURCE` to a clone containing that pin until it is available upstream. Review Nervelet before the dependent DroneRTS change. Emergency attention and acoustics remain independently off unless their `FLEET_ATTENTION` / `FLEET_ACOUSTIC` value is `experimental`. Do not turn protocol fixtures into autonomy or calibrated-sensor claims.
- `npm run dev` serves [the game](http://127.0.0.1:4317). `npm run build` checks TypeScript and creates the production bundle; `npm start` serves it.
- `npm test` runs deterministic and real native Zenoh/MAVLink integration tests without model inference. Run relevant tests and the build after implementation changes.
- Live gameplay requires an installed, signed-in Codex CLI and an open camera browser. Launch gives both teams the same objective and gates simulation/movement/spending until all six pilots have received it in actual tool bundles; ordinary player chat addresses blue only and does not replace objectives.
- All gameplay actors and live playtest agents use **gpt-5.6-luna / xhigh**. The backend/model configuration is explicit and no fallback is permitted. This cost preference is scoped to gameplay/playtesting.
- Before any restart or trial, inspect `/api/state`. Preserve active player port 4317; prefer isolated 4318. If occupied by another checkout, `playtest-focused.ts` supports `RTS_TRIAL_PORT` for another free port and rejects player port 4317 or an occupied trial port. Bound trials and stop owned actors/helpers/server afterward.
- Prefer the Codex sidebar browser for watchable playtests; isolated Playwright is authorized. Do not launch inference for documentation-only work.
- `node --import tsx scripts/verify-rts.ts` is a deterministic browser fixture. `scripts/playtest-rts.ts` and `scripts/playtest-focused.ts` launch actual Luna/xhigh actors. Check README for exact commands. Analyze saved evidence before claiming autonomy, moving-target hits or emergent coordination.
- Prove deterministic conservation/control/runtime gates, then autonomous single haul, repeated haul, useful team haul, and only then full battle. Fixtures prove mechanics, not model perception. Current measured evidence belongs in `RTS-PLAYTEST.md`; preserve historical reports.

## Preserve the experiment

- Two isolated teams of three clean-context native drone actors. Parents mechanically forward exact original team instructions; they do not plan, assign roles, choose loadouts or solve missions. Use `MATCH_FLEET`/`MATCH_DRONE_IDS` for all six drones; the default roster is three.
- The inference engine/model is an abstracted onboard brain. This exemption includes inference hardware/weights only; it does not exempt local scripts, optional vision libraries, storage, CPU, tool latency or actor isolation. Keep Codex first behind the bounded backend contract; additional providers require equivalent tests and explicit configuration.
- Agents observe only their own acquired pixels, local XYZ/velocity, heading, measured camera orientation, timestamped finite range sensors, own equipment/cargo/jobs/storage, unlocked shared balance and actual delivered messages. No body roll/pitch dynamics exist. One simulation unit is ten meters; expose conversion, axes, camera calibration, actuator/service limits and sensor coverage as vehicle knowledge.
- Keep battlefield geometry, resource/base coordinates, opponent telemetry, internal collision shapes, combat formulas, future frames and player maps outside actor tools and files. No arbitrary pixel-to-world raycast, automatic object classifier, hidden locator or global pathfinder. Local ranges return anonymous finite distances and validity, never object IDs or contact coordinates.
- Keep common recognition/rules/vehicle briefing in `shared/mission.ts`. At mission opening, each pilot sends one brief team message acknowledging that it is online, then proceeds without waiting for replies or negotiating an opening plan or first purchase. Encourage active coordination throughout: promptly share useful discoveries, intentions, progress, threats and requests for help, answer actionable questions, refine plans together and coordinate shared spending; avoid repeated unchanged status and acknowledgement loops. Prescribe no tactics, roles, purchases, exploration routines, routes, positions, radio formats or reporting schedules. Explicit player text relays unchanged.
- Salvage uses visible matte yellow/ochre crates on dark pallets and marked loading aprons. Automatic low/slow service loads finite stock into cargo after three simulation seconds; friendly-base delivery banks it after two. One free grip carries 30; the cargo module carries 60; loaded maximum speed is 20% lower. Shared `CARGO_CONFIG` defines service bands/speed/footprints. No camera gate, tiny-crate target, resource locator, passive income or regeneration.
- Stock reservations, loading cancellation, interrupted delivery, atomic deposits, partial stock, destruction loss/recovery, Stop and reset conserve value. Incomplete loading releases reservations; interrupted delivery retains cargo. Recoverable drops remain at an accessible actual crash site; otherwise cargo is lost. Never teleport salvage or reveal a drop locator.
- Each team starts with zero shared salvage. Every drone starts unarmored, with empty module slots and the free grip. Two module slots accept gun/cargo at 30 each; replacement armor costs 20 outside slots. Optics, battery, miner upgrade and jammer purchases/tools are absent from new matches; retain only historical interpretation.
- Fit/replace equipment at friendly service occupancy, atomically and without resale refunds or free ammo. Current bases accept drone centers inside the painted footprint from 0 through 6 local units above its surface; this service calibration is allowed actor knowledge. Guns have 12 finite rounds; rearming costs 10 and takes eight uninterrupted simulation seconds with exactly-once cancellation refunds. Cargo unloading uses its separate low/slow band and can overlap rearming. Flight has no endurance limit: no battery state, drain, charging, battery module, recharge tool or power-loss death in current matches. Keep historical energy fields/rules only for old recordings and explicit legacy fixtures.
- Marked aprons fit three separated airframes and add no solid collision clutter. Preserve physical aiming, friendly fire, one-hit armor, lethal unarmored terrain/building/drone contact, armor deflection and last-team-standing victory. Current gun kills leave a dark, unlit falling wreck and slowly dissipating physical smoke; death, cargo resolution and actor retirement remain immediate. Wrecks are cosmetic debris without new collision or sensor capabilities. Acquired images use their own snapshot/time, while spectator death effects may finish after victory. Other deaths and historical recordings without effect metadata retain disappearance. Generic collision/armor-loss or hit/armor-loss alerts reveal no attacker, obstacle identity or impact coordinates. Armor loss stops movement.
- One movement writer owns each drone. Ordered routes and authored routines return prompt job admission, explicit completion/blocked/cancelled/failed state and source provenance. Replacement is explicit. Healthy local execution renews a 500 ms monotonic controller lease without model keep-alives. Local braking uses only modeled finite range coverage and never reroutes. Stale/invalid sensing, controller failure, expired leases, received objective change, Stop/reset, death and invalid capability cancel affected work and prevent stale side effects.
- Fresh camera/telemetry/inbox bundles arrive at direct tool and aggregate exchange boundaries. Native pilots use one embedded Nervelet Bridge each: only an echoed `seen` bundle ID consumes included mail and the exact included result revisions. Original operation output belongs only in `nervelet.results[].data`, separate from current state; resolved acknowledgement releases its payload while scalar deduplication remains. Preflight result storage and wire budgets reject new effects before execution when full. The 128 KiB event slice and `hasMore` preserve backlogs. Recovery gates new effects until a fresh bundle is acknowledged. Batches have at most eight compatible operations with individual results and no rollback claim; dependent actions belong in ordered jobs/routines. Cancellation must remain responsive during waits, camera encoding and transfer. Local control/routines continue while a model thinks; private reasoning is not an input-injection boundary.
- Advertise the stable current-ruleset catalog while keeping `availableTools` and dispatch authority dynamic. Equipment changes do not require catalog-yield turns. Use scoped onboard notifications for affected pilots and explicit lifecycle/connection signals; ordinary UI changes and idle ticks must not reacquire telemetry for plain event waits. Numeric conditions retain continuous updates.
- Ordinary chat does not replace an objective or cancel work. Explicit objective changes apply only after that drone actually receives them. Radio loss does not stop valid local flight or scripts. Preserve two native Zenoh networks, each three drones plus its operator, and six distinct MAVLink 2 vehicle identities. Missing helpers/errors stay explicit; no live in-memory transport fallback. Loopback partitions are not a physical RF mesh or full autopilot.
- Workspaces are private, atomic and empty on new matches; destruction revokes access. Enforce the fixed 16 MiB application split: runtime/SDK 8, workspace 2, durable radio 4, staging 1, logs/cache 1. Logs/cache reserves 512 KiB for unread local events and 512 KiB for rotating diagnostics; exhaustion must not silently evict unread events. Workspace files are at most 64 KiB and 256 files; names/metadata/retained versions count. Optional guest libraries total at most 256 KiB. Measure deployed/transitive assets and manifest; never enlarge quotas or hide optional host libraries.
- QuickJS executes behind a terminable worker with RAM/CPU/operation/deadline bounds, no shell/network/host files and only the permitted SDK. Code transfers are bounded, low-priority, hash-verified and inert until explicit recipient import; no shared team folder, automatic execution, compression or archives. Each copy costs storage. Never evict unread mail or authored files silently; report capacity backpressure before receipt. Bound persistent metadata/deduplication/WAL growth too.
- Keep queue/storage receipt, actual bundle inclusion, explicit reply and completed action distinct. Sender identity is host-bound; namespace is not cryptographic authentication. Retry/expiry and runtime budgets use monotonic host time; physics/service timers use simulation time. First protocol/autonomy measurements run fixed 1x; timestamp acquisition/delivery separately.
- Replay samples routine poses every 0.5 seconds, forces frames at command/event boundaries and reserves a final outcome summary even if detailed coverage fills. Replay is a bounded player-only archive of actual poses, cargo/service/jobs, delivered income, radio stages, script hashes/versions and executed SDK events. Never execute replay code or refill later actors from archived knowledge. Do not invent authoritative team plans from private reasoning.
- Preserve OpenStreetMap attribution and documented approximations. Sources are in [CINCINNATI-SOURCES.md](CINCINNATI-SOURCES.md); regenerate `shared/city-data.json` with `node scripts/build-city.mjs` after source changes.
