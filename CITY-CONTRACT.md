# Cincinnati increment ownership and interfaces

Root owns shared/types.ts, shared/city.ts, shared/city-data.json, scripts/build-city.mjs, server/, tests/, README and CITY.md. Research maker owns city-research.json and CINCINNATI-SOURCES.md. Visual maker owns client/ and may add client/city-scene.ts, no server/shared edits. Playtest maker later owns scripts/playtest-city.ts and CITY-PLAYTEST.md/artifacts only. One final independent review after join; root owns one repair pass.

`CITY` from shared/city.ts is renderer/simulator-only layout. Local X east, Z south; one unit = 10 metres; origin Fountain Square 39.1015,-84.512. These calibrations are forbidden in model inputs. Bounds/spawns/roads/parks/river/buildings are in local units. Roads have name, points [{x,z}], width. Parks have name, points, optional color. River is a polygon. Buildings match `Obstacle`: centre x/z, width/depth/height, rotation degrees around THREE positive Y, optional baseY, id, name, color. Buildings must render exactly these collision boxes; decorative faces/windows can be coplanar/within box extent.

GameState replaces pads with treasures: [{id,x,y,z,found,foundBy?,foundAt?}]. Treasure y is the base elevation. Prop dimensions should be approximately 1.4 wide × 1.0 deep × 1.1 tall: deliberately oversized toy chests, golden bands, brown panels; found state can open lid inside the same prop bounds. No floating through-wall treasure icons, waypoints or location HUD for drones. Static city render group separate from dynamic treasure group; don't rebuild all city meshes on every discovery.

Default mission: "Find the treasure chests scattered around the city. Fly close enough to inspect each chest with your camera, then report it to the fleet using a found radio message. Share discoveries and coordinate your search." This is player-facing mission text, sent unchanged through existing relay on Send. Model system prompts remain world-agnostic. Player HUD shows treasure count, not undiscovered chest coordinates. Discovery scoring uses a nearby clear camera observation plus a found radio report mentioning chest/treasure; scorer never sends hidden positions, count or success events to agent inboxes. Tests and developer docs may access all world data.

FleetScene preserves 512×288 camera capture, heading convention, own-drone hiding and snapshot peer positions. Range/fog/shadows must cover ~200×190-unit city and ~21-unit tallest tower. Use bright simple cube graphics, readable streets/parks/river, some visual street/place labels physically in the world if useful. UI should keep three FPV feeds prominent, show Cincinnati title and treasure progress, and keep network controls working. Actual dataset is being researched; code can consume the present typed CITY interface before population. All gameplay and live playtest actors remain Luna/xhigh.
