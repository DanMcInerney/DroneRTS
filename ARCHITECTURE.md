# RTS ownership and observation boundaries

The offline audit lives exclusively in `scripts/audit/`: the loader owns safe bounded reads and input identity, the decoder owns recorded MCP/error parsing, correlation owns bundle and acquisition joins, checks own DroneRTS evidence policy, and reporting owns deterministic output. `scripts/analysis-boundaries.ts` is the shared native call/completion join used by all analysis consumers. No runtime or actor imports these modules, and Nervelet remains an unchanged general library.

`scripts/audit-run.ts` is only the offline CLI. The focused runner delegates its close/collect/save/audit sequence to `scripts/finalize-focused-trial.ts`; it never audits unclosed writers. `scripts/test-artifacts.ts` continues to own registration, collection and retention. The auditor creates only derived reports and cannot launch actors, execute archived programs or contact the network. [Audit design](https://github.com/DanMcInerney/DroneRTS/blob/72717d725166f5e4dca1870c55640152ed9e0d49/OFFLINE-AUDIT-DESIGN.md) and [implementation QA](https://github.com/DanMcInerney/DroneRTS/blob/72717d725166f5e4dca1870c55640152ed9e0d49/OFFLINE-AUDIT-QA.md) describe the supported checks and evidence gaps.

A match has two teams of three drones, two mechanical native parents and one authoritative simulator. Gameplay uses explicit Luna/xhigh configuration. The blue and red runtimes start independently with clean actor contexts. Parents relay exact original objectives without planning; each drone chooses its own movement, hauling, spending, aiming, private code and delivered messages.

## One concept, one owner

The native pilot path passes through one embedded Nervelet Bridge per drone in `server/nervelet.ts`. It owns acknowledgement/recovery/receipt coordination; the game retains sensors, jobs, mission receipt, quotas and cancellation. Original command output is retained as immutable `nervelet.results[].data = {result, isError}`, separately from current observation state. Core and the original execution record share that payload until the delivered resolved revision is acknowledged. `DRONE_BINDING` supplies aliases for translation and generated protocol instructions; the profile supplies numeric wait identifiers, paths, freshness and meanings. Existing direct tools are aliases: omitted-`until` `wait` selects any unread event and `exchange` is the only batch interface. Scoped `onboard-change` notifications affect only the relevant pilot; lifecycle/connection signals abort affected waits, and numeric conditions alone receive tick updates. `TeamSession` retains native actor hosting. See [Nervelet integration](NERVELET-INTEGRATION.md).

Optional attention uses the same Bridge and native runtime. `server/onboard-attention.ts` selects retained local evidence and governs episode/rearm eligibility; Nervelet owns transition/reconciliation. `server/runtime.ts` joins exact native termination with outstanding HTTP/result and native tool work, then submits fresh recovery/image to the same child. Final MCP HTTP submission is confirmed separately from bundle assembly, pilot acknowledgement and completed action. No second supervisor exists. `server/acoustic-sensor.ts` is an independently gated game-owned finite sensor; private world stimuli become uncertain local measurements before reaching the adapter. It supplies no source identity, coordinates or motion policy.

## Isolation and temporal meaning

`GameState` is the omniscient player/browser contract. A drone receives its own acquired pixels and state, permitted calibration, finite sensor distances, local feedback and actually delivered messages. One simulation unit equals ten meters. Exposing axes, sensor coverage or camera projection does not disclose resource coordinates, opponent poses, map bounds or authoritative collision shapes.

The new observation contract labels sample sequence, local frame, units, acquisition time, host age and validity. Camera-associated pose stays attached to that frame; newer telemetry is separately labeled. Range sensors are a modeled capability, not an automatic consequence of adding MAVLink. State estimates are idealized. Neither observed free space nor a beam sample proves an entire route safe.

Direct calls and aggregate exchanges attach fresh images and the next unread event slice at supported model boundaries. A `hasMore` result preserves remaining unread events for subsequent boundaries; exhausting local event capacity stops the host explicitly rather than silently discarding unread history. Admission is separate from long movement, waits, camera capture and transfer. Every batch entry has its own outcome; completed effects do not roll back. A route is sequential; a routine can combine its own logic with the same authoritative SDK. One movement writer and explicit replacement prevent silent races. Mission, capability and owner checks occur again after asynchronous work before committing side effects.

Objectives take effect only when received by that drone through the team's native network. Ordinary player/peer chat is independent of objectives. Radio partitions preserve valid local work and the last received mission. Stop is host cleanup, not a message crossing a broken radio. Death/Stop/reset, invalid capabilities, stale required sensing, lease failure and received objective changes invalidate affected work. Collision absorption stops movement. Domain cancellation occurs immediately when the game receives an objective; the later Bridge stop is idempotent. This preserves standalone Bridge ownership and exactly-once refunds.

The advertised tool catalog and exchange operation schema describe the current ruleset, including permitted equipment tool names before purchase. `availableTools`, dispatch and every admitted exchange operation still require current equipment and actor authority. Removed historical optics/camera tools remain absent. Equipment changes no longer yield or resume native turns; ordinary continuation, exact terminal/tool/result joins, compaction correlation, emergency settlement and actor-retirement catalog revocation remain owned by the runtime.

The inference hardware/weights exemption does not grant host storage or arbitrary SDK access. Every drone has its own quota-accounted workspace and restricted QuickJS worker. File transfers use real native mail; received code remains in charged staging until hash verification and recipient-chosen import. No automatic shared folder, world cache, target classifier or solved routine exists. Native Python/network/vehicle bridges are fixed platform infrastructure, outside guest imports. [ONBOARD.md](ONBOARD.md) documents the exact scope and budgets.

## Reasoning visibility

`server/runtime.ts` requests `model_reasoning_summary = "auto"` and `show_raw_agent_reasoning = true` for new Luna/xhigh actors, using the documented [Codex settings](https://developers.openai.com/codex/config-reference). The adapter keeps `item/reasoning/textDelta` and completed readable `reasoning.content` separate from `item/reasoning/summaryTextDelta` and completed `reasoning.summary`, following the [app-server event contract](https://learn.chatgpt.com/docs/app-server#item-deltas). Streaming updates stay in the bounded cockpit; sanitized completed/interrupted partial records persist in audits. Availability describes emitted readable text, without claiming the model's full internal reasoning. New settings do not change existing actors or recover discarded historical text; live Luna stream support has not yet been confirmed.

## Replay and historical evidence

Replay subscribes to authoritative state and completed deliveries, with byte limits and bounded asynchronous queues. Actual captured pixels are separate from redacted audit summaries. Recorded cargo, service/job progress, radio stages and immutable script source versions are spectator evidence. They cannot refill an actor's inbox or private filesystem. A shared plan appears only as actual observed/reported content; private reasoning does not become an omniscient team plan.

The viewer interprets recorded rules and geometry. Older cube/miner/jammer recordings retain their meaning rather than becoming cargo matches. It shows recorded frames at/before the cursor, acquisition age and omissions, never future interpolation. Replaying JavaScript source is display only. Reports identify the source revision they tested.

## Verification

Use focused cargo conservation, observation, local-control, job, workspace/runtime, protocol and runtime-policy tests, then `npm run build`. The broad suite includes actual Zenoh/MAVLink helpers with no model inference. Deterministic browser fixtures inspect acquired camera pixels; they do not establish autonomous recognition, hauling or coordination.

Bounded live evaluation uses Luna/xhigh, an owned isolated server and actual camera browser. Preserve active port 4317 and use another free trial port if 4318 is occupied. Autonomous single-haul/repetition and useful team hauling precede another full battle. The historical [playtest record](https://github.com/DanMcInerney/DroneRTS/blob/72717d725166f5e4dca1870c55640152ed9e0d49/RTS-PLAYTEST.md) contains measured evidence and limitations; historical reports do not validate later features.

The downtown extent is centralized in `shared/downtown.json`; generation clips roads, parks and water and culls wholly outside building boxes, leaving retained building dimensions unchanged. Replay headers retain their own scene bounds, so historical maps stay interpretable. New recordings sample routine poses at 0.5 seconds and force frames at commands/events, with a reserved final outcome summary independent of detailed coverage.
